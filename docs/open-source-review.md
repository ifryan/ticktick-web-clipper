## P1 — 源码安装的 OAuth 回调缺少通用分发方案

Manifest 未固定扩展 ID，OAuth 使用浏览器实际生成的回调地址。仓库中的公共 Client ID 绑定维护者登记的应用，其他安装环境生成的回调不一定已登记。此前国际版登录失败已通过补登记当前安装的回调解决，但这不能证明其他机器可以直接使用内置应用登录。

建议为正式发行确定稳定扩展身份和对应回调，在发布包与应用登记之间建立可核对的记录。源码贡献者使用自己的应用时，应遵循 README 中的回调配置步骤。此项已补充文档，正式分发方案仍待实现。

## P1 — 创建失败可能被弹窗当作成功

`clipToTickTick()` 会捕获任务创建异常，401 分支也会直接返回。`clipTab` 消息入口等待该函数结束后，无条件返回 `success: true`。弹窗因此可能在任务没有创建成功时关闭，用户失去重试入口。

建议让剪藏函数明确返回创建结果或向调用者传播失败，并由工具栏、右键和弹窗入口分别处理。验收应覆盖 API 非 2xx、网络失败、授权过期、正文提取失败和正常创建。

[剪藏结果处理](../src/js/clipper.js) · [后台消息](../src/service-worker.js) · [弹窗保存](../src/popup/popup.js)

## P1 — 访问令牌跟随普通设置同步

`storage.location` 指向 `chrome.storage.sync`，OAuth 令牌与设置一起写入该存储区。浏览器启用同步后，这些值可能跨设备传播。国内版、国际版的令牌按服务隔离，但存储介质相同。

建议单独设计令牌的存储和迁移，普通偏好继续同步，凭证根据登录持久化需求使用受信任扩展上下文中的本地或会话存储。修改时需要迁移已有用户数据并覆盖两版服务。README 已披露当前行为。Chrome 官方文档对敏感数据建议使用会话存储。

[存储实现](../src/js/store.js) · [令牌写入与登出](../src/js/ticktick-api.js) · [Chrome Storage](https://developer.chrome.com/docs/extensions/reference/api/storage)

## P2 — 弹窗标题没有进入任务创建链路

弹窗读取标题输入框并生成 `overrides.popupTitle`，但随后只保存清单、优先级、日期和正文开关。`clipTab` 消息未携带标题，剪藏函数仍使用 `tab.title` 构造任务标题。输入框可以编辑，但结果没有应用。

建议定义一次剪藏的参数，并通过后台消息传递到任务创建函数。验收时使用与网页标题不同的文本，核对创建后的任务标题和来源链接。

[弹窗参数](../src/popup/popup.js) · [后台入口](../src/service-worker.js) · [标题构造](../src/js/clipper.js)

## P2 — 弹窗单次选择直接覆盖默认设置

弹窗保存前调用 `setOptions`，清单、优先级、日期和正文开关会永久改变。请求创建任务失败时，这些偏好也已经写入。实现注释称临时覆盖，实际行为是持久化，用户也没有单独的保存默认值操作。

建议明确产品行为，再使用单次剪藏参数，或在界面中明确说明默认值会更新。本次 README 已说明当前持久化行为。

[弹窗保存流程](../src/popup/popup.js) · [设置写入](../src/js/store.js)

## P2 — 账号信息依赖未列出的用户接口

登录信息显示调用 `GET /open/v1/user/info`。本次核对的国内版和国际版官方 Open API Markdown 均未列出该路径，实际返回结构与两版兼容性还未联调。接口失败会回退为「已登录（账号信息暂不可用）」；当前登录判断只检查令牌是否存在。

建议分别核对真实服务返回，记录接口兼容性和账号字段。账号资料请求应保持独立于创建任务的关键流程。现实现已异步读取，新增成本为每次打开已登录界面的一次资料请求。

## P2 — 页面标题参与 HTML 与 Markdown 拼接

页内通知将网页标题直接插入 `innerHTML`。标题包含 HTML 标记时会被当作 DOM 解析，可能改变通知内容与布局。普通网页标题也直接放入 Markdown 链接标签，包含方括号时可能破坏链接。选区标题已有转义，普通标题路径没有复用。

建议用 DOM API 和 `textContent` 构造通知，把任务链接作为独立 URL 属性设置，并统一标题的 Markdown 转义。该发现说明了内容解析边界，尚未证明存在扩展权限提升。

[通知构造与标题](../src/js/clipper.js)

## P2 — 全文中的井号替换会改变链接

全文转换后对所有 Markdown 运行井号替换。URL 的 `#section` 也会被改为 `#/section`，从而改变原锚点。选区转换采用单独路径，已经避免这一全文替换。

建议在 Markdown 文本节点或标签生成处处理目标行为，并核对标题、代码块、内联代码和锚点链接。当前用标签设置生成的文字也仅附加在正文，尚未提交原生 `tags` 字段。
